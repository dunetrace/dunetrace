# Examples Index

This directory contains self-contained example scripts that demonstrate how to use Dunetrace in various agents and frameworks.

Each example includes a docstring that describes its purpose, how to run it, and any required environment variables or setup steps.

Below is a summary of all available examples. Run commands are relative to the
directory shown in the **Example** column: run root examples (`examples/…`) from
the repo root, and SDK examples (`packages/sdk-py/examples/…`) from
`packages/sdk-py/`.

| Example | Description | Run Command | Stack Requirement |
|---------|-------------|-------------|-------------------|
| examples/approval_agent.py | Human-in-the-loop approval example (Capability 2). A `require_approval` policy gates the `wire_money` tool: when the agent tries to call it, the run blocks until a human approves in Slack or the dashboard — or the request times out, which is fail‑Closed (the tool is blocked, not allowed). | `docker compose up -d`<br>`python examples/approval_agent.py` | Requires a running stack |
| examples/delegation_loop_agent.py | Multi-agent delegation‑loop example (Capability 2). Two agents — a planner and an executor — delegate to each other. Each agent is its own `dt.run();` because a nested run auto‑inherits the active run's ID as its parent_run_id (no manual threading — see docs/multi-agent.md), the recursive delegation builds a run graph: planner → executor → planner → executor → … | `docker compose up -d`<br>`python examples/delegation_loop_agent.py` | Requires a running stack |
| examples/memory_agent.py | Memory agent example (Capability 1). Agents persist things to memory — a scratchpad, a conversation buffer, a long‑term store — and read them back later. That memory is an attack surface: content from an untrusted channel (a retrieved document, a tool response) can be summarized and saved verbatim, injection and all, then re‑steer the agent every time it's loaded back. | `docker compose up -d`<br>`python examples/memory_agent.py` | Requires a running stack |
| examples/voice_agent.py | Voice agent example — instrumenting a real‑time voice call with Dunetrace and the voice detector pack. | `docker compose up -d`<br>`python examples/voice_agent.py` | Requires a running stack |
| packages/sdk-py/examples/autogen_agent.py | AutoGen agent example: Dunetrace monitoring for a multi‑agent conversation. Shows an AssistantAgent + RoundRobinGroupChat monitored via DunetraceAutoGenObserver. Every LLM call is tracked by wrapping the model client with DunetraceModelClient. | `pip install 'dunetrace' autogen-agentchat autogen-ext python-dotenv`<br>`OPENAI_API_KEY=sk-... python examples/autogen_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-py/examples/basic_agent.py | Manual instrumentation example — full control over every event. For most agents, the `@dt.agent()` decorator in `decorator_agent.py` is simpler. Use this when you need fine‑grained control or are integrating with a framework that lacks dedicated middleware. | `pip install dunetrace`<br>`python examples/basic_agent.py`<br>(Sends events to http://localhost:8001; start the backend first with `docker compose up`) | Requires a running stack |
| packages/sdk-py/examples/crewai_agent.py | CrewAI agent example: Dunetrace monitoring for a CrewAI crew. | `pip install 'dunetrace[crewai]' crewai`<br>`OPENAI_API_KEY=sk-... python examples/crewai_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-py/examples/decorator_agent.py | Minimal example using `@dt.agent()` decorator + `auto_instrument()`. This is the recommended starting point for pure Python agents that call OpenAI or Anthropic directly. Zero changes to your LLM call sites. | `pip install dunetrace`<br>`python examples/decorator_agent.py` `# happy‑path runs`<br>`SCENARIO=failures python examples/decorator_agent.py` `# signal‑triggering runs`<br>(Sends events to http://localhost:8001; start the backend first with `docker compose up`) | Requires a running stack |
| packages/sdk-py/examples/haystack_agent.py | Haystack 2.x agent example for Dunetrace monitoring. Registers DunetraceHaystackTracer once at startup — no pipeline changes needed. | `pip install 'dunetrace[haystack]' haystack-ai openai python-dotenv`<br>`python examples/haystack_agent.py` `# RAG pipeline`<br>`SCENARIO=tool_loop python examples/haystack_agent.py` `# triggers TOOL_LOOP signal` | Requires a running stack |
| packages/sdk-py/examples/hermes_agent.py | Hermes Agent + Dunetrace integration example. Scenarios (set `SCENARIO` env var):<br>• `SCENARIO=happy` — normal run: tool called, LLM responds, run completes<br>• `SCENARIO=tool_loop` — TOOL_LOOP: same tool called 4× with identical args<br>• `SCENARIO=retry` — RETRY_STORM: tool fails 3 consecutive times<br>• `SCENARIO=abandon` — GOAL_ABANDONMENT: LLM calls with no tools, no answer<br>• `SCENARIO=real` — runs a real Hermes agent (requires `OPENAI_API_KEY`)<br>• `SCENARIO=real_loop` — runs a real Hermes agent that provokes a tool loop<br>Default runs all synthetic scenarios (no credentials needed). | `PYTHONPATH=packages/sdk-py python examples/hermes_agent.py` `# all synthetic scenarios`<br>(See docstring for details on real‑world scenarios) | Requires a running stack |
| packages/sdk-py/examples/langchain_agent.py | LangChain agent example: Dunetrace monitoring for a LangChain agent that uses tools. | `pip install 'dunetrace[langchain]' langchain-openai`<br>`OPENAI_API_KEY=sk-... python examples/langchain_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-py/examples/openai_agents_agent.py | OpenAI Agents SDK example: Dunetrace monitoring for an OpenAI Agents agent. | `pip install 'dunetrace[openai-agents]' openai-agents`<br>`OPENAI_API_KEY=sk-... python examples/openai_agents_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
