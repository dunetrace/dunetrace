# Examples Index

This directory contains self-contained example scripts that demonstrate how to use Dunetrace in various agents and frameworks.

Each example includes a docstring that describes its purpose, how to run it, and any required environment variables or setup steps.

Below is a summary of all available examples. Run commands are relative to the
directory shown in the **Example** column: run root examples (`examples/…`) from
the repo root, Python SDK examples (`packages/sdk-py/examples/…`) from
`packages/sdk-py/`, and TypeScript SDK examples
(`packages/sdk-ts/examples/…`) from `packages/sdk-ts/`.

> **Some of these cost money.** The framework examples — AutoGen, CrewAI,
> Haystack, LangChain, OpenAI Agents, and Hermes' `SCENARIO=real*` — make real
> LLM API calls. All but Hermes also `load_dotenv()` the repo-root `.env`, so
> they will pick up an `OPENAI_API_KEY` from there **even when you don't pass
> one on the command line** (the `OPENAI_API_KEY=sk-...` prefixes below show
> where the key is read from, not a requirement to set it inline); Hermes reads
> the ambient environment only. Everything else — `basic_agent`,
> `decorator_agent`, the root `examples/` scripts, and Hermes' default synthetic
> scenarios — simulates its LLM calls and costs nothing.
>
> The TypeScript example is a separate case: its agent runs against a **local
> Ollama**, so the agent's own LLM calls are free, but `SCENARIO=tool_loop`
> additionally calls `POST /v1/signals/{id}/explain`, which spends one LLM call
> on whatever provider *the stack* is configured with.

| Example | Description | Run Command | Stack Requirement |
|---------|-------------|-------------|-------------------|
| examples/approval_agent.py | Human-in-the-loop approval example (Capability 2). A `require_approval` policy gates the `wire_money` tool: when the agent tries to call it, the run blocks until a human approves in Slack or the dashboard — or the request times out, which is fail‑Closed (the tool is blocked, not allowed). | `docker compose up -d`<br>`python examples/approval_agent.py` | Requires a running stack |
| examples/delegation_loop_agent.py | Multi-agent delegation‑loop example (Capability 2). Two agents — a planner and an executor — delegate to each other. Each agent is its own `dt.run();` because a nested run auto‑inherits the active run's ID as its parent_run_id (no manual threading — see docs/multi-agent.md), the recursive delegation builds a run graph: planner → executor → planner → executor → … | `docker compose up -d`<br>`python examples/delegation_loop_agent.py` | Requires a running stack |
| examples/memory_agent.py | Memory agent example (Capability 1). Agents persist things to memory — a scratchpad, a conversation buffer, a long‑term store — and read them back later. That memory is an attack surface: content from an untrusted channel (a retrieved document, a tool response) can be summarized and saved verbatim, injection and all, then re‑steer the agent every time it's loaded back. | `docker compose up -d`<br>`python examples/memory_agent.py` | Requires a running stack |
| examples/voice_agent.py | Voice agent example — instrumenting a real‑time voice call with Dunetrace and the voice detector pack. | `docker compose up -d`<br>`python examples/voice_agent.py` | Requires a running stack |
| examples/vapi_webhook_agent.py | Vapi + Dunetrace integration. Vapi is cloud‑orchestrated: it runs the STT/LLM/TTS pipeline and posts server messages to your webhook. `DunetraceVapiAdapter` turns those into voice events, buffering each call and replaying it as one run when the call ends. Self‑contained — feeds a scripted message sequence through the adapter instead of needing a live phone call. | `docker compose up -d`<br>`python examples/vapi_webhook_agent.py` | Requires a running stack |
| otel/exercise_agent.py | OpenTelemetry export demo — runs one agent exercising every span type (run, LLM, tool, HTTP tool, retrieval, voice) plus the server‑side signal/policy spans, and ships them to a local OTel backend. Verifies the run lands with the right conventions. See [docs/integrations/opentelemetry.md](../docs/integrations/opentelemetry.md). | `docker compose -f otel/docker-compose.yml up -d`<br>`python otel/exercise_agent.py`<br>`python otel/verify.py` | Requires the OTel harness (otel/docker-compose.yml), not the Dunetrace stack |
| packages/sdk-py/examples/autogen_agent.py | AutoGen agent example: Dunetrace monitoring for a multi‑agent conversation. Shows an AssistantAgent + RoundRobinGroupChat monitored via DunetraceAutoGenObserver. Every LLM call is tracked by wrapping the model client with DunetraceModelClient. | `pip install dunetrace autogen-agentchat autogen-ext python-dotenv`<br>`OPENAI_API_KEY=sk-... python examples/autogen_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-py/examples/basic_agent.py | Manual instrumentation example — full control over every event. For most agents, the `@dt.agent()` decorator in `decorator_agent.py` is simpler. Use this when you need fine‑grained control or are integrating with a framework that lacks dedicated middleware. | `pip install dunetrace`<br>`python examples/basic_agent.py`<br>(Sends events to http://localhost:8001; start the backend first with `docker compose up`) | Requires a running stack |
| packages/sdk-py/examples/crewai_agent.py | CrewAI agent example: Dunetrace monitoring for a CrewAI crew. | `pip install dunetrace crewai python-dotenv`<br>`OPENAI_API_KEY=sk-... python examples/crewai_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-py/examples/decorator_agent.py | Minimal example using `@dt.agent()` decorator + `auto_instrument()`. This is the recommended starting point for pure Python agents that call OpenAI or Anthropic directly. Zero changes to your LLM call sites. | `pip install dunetrace`<br>`python examples/decorator_agent.py` `# happy‑path runs`<br>`SCENARIO=failures python examples/decorator_agent.py` `# signal‑triggering runs`<br>(Sends events to http://localhost:8001; start the backend first with `docker compose up`) | Requires a running stack |
| packages/sdk-py/examples/haystack_agent.py | Haystack 2.x agent example for Dunetrace monitoring. Registers DunetraceHaystackTracer once at startup — no pipeline changes needed. | `pip install 'dunetrace[haystack]' python-dotenv`<br>`OPENAI_API_KEY=sk-... python examples/haystack_agent.py` `# RAG pipeline`<br>`SCENARIO=tool_loop python examples/haystack_agent.py` `# triggers TOOL_LOOP signal` | Requires a running stack |
| packages/sdk-py/examples/hermes_agent.py | Hermes Agent + Dunetrace integration example. Scenarios (set `SCENARIO` env var):<br>• `SCENARIO=happy` — normal run: tool called, LLM responds, run completes<br>• `SCENARIO=tool_loop` — TOOL_LOOP: same tool called 4× with identical args<br>• `SCENARIO=retry` — RETRY_STORM: tool fails 3 consecutive times<br>• `SCENARIO=abandon` — GOAL_ABANDONMENT: LLM calls with no tools, no answer<br>• `SCENARIO=real` — runs a real Hermes agent (requires `OPENAI_API_KEY`)<br>• `SCENARIO=real_loop` — runs a real Hermes agent that provokes a tool loop<br>Default runs all synthetic scenarios (no credentials needed). | `pip install dunetrace hermes-agent`<br>`python examples/hermes_agent.py` `# all synthetic scenarios`<br>(See docstring for details on real‑world scenarios) | Requires a running stack |
| packages/sdk-py/examples/langchain_agent.py | LangChain agent example: Dunetrace monitoring for a LangChain agent that uses tools. | `pip install 'dunetrace[langchain]' langchain-openai python-dotenv`<br>`OPENAI_API_KEY=sk-... python examples/langchain_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-py/examples/openai_agents_agent.py | OpenAI Agents SDK example: Dunetrace monitoring for an OpenAI Agents agent. | `pip install 'dunetrace[openai-agents]' python-dotenv`<br>`OPENAI_API_KEY=sk-... python examples/openai_agents_agent.py`<br>(Set `SCENARIO=tool_loop` to trigger a TOOL_LOOP signal) | Requires a running stack |
| packages/sdk-ts/examples/vercel_ai_agent.ts | TypeScript example: Dunetrace + the Vercel AI SDK. Drives `generateText` against a **local Ollama** via its OpenAI‑compatible endpoint, so no API key is needed. The run is opened with the `traceGenerateText` wrapper, which emits the same `llm.*` / `tool.*` events a manual loop would. `SCENARIO=tool_loop` provokes a TOOL_LOOP, polls for the signal, then calls `POST /v1/signals/{id}/explain` and prints the root cause and fix. | `npm install`<br>`ollama pull llama3.2`<br>`npm run example:vercel-ai`<br>`npm run example:vercel-ai:loop` `# TOOL_LOOP + explain` | Requires a running stack **and** a local Ollama |
